## 🔍 逻辑错误根因分析

### 问题现象
首页4个分类图标（果酒系列/粮食酒系列/NFC果汁系列/礼盒套装）点击后，无法正确跳转到对应产品列表页面。

### 根因1：分类ID映射不一致（核心问题）

首页 `index/index.tsx` 的分类入口跳转逻辑：
```ts
onClick={() => router.push({ url: `/pages/category/index?category=${cat.id}` })}
```

这里传的 `cat.id` 来自 `MOCK_CATEGORIES`，值为 `'cat_pear'`、`'cat_pomegranate'`、`'cat_hawthorn'`、`'cat_gift'`。

但 `category/index.tsx` 的分类筛选逻辑：
```ts
const categories = [
  { id: 1, name: '全部', icon: '🏠' },
  { id: 2, name: '果酒', icon: '🍑' },
  { id: 3, name: '果汁', icon: '🫐' },
  { id: 4, name: '气泡酒', icon: '🍓' },
  { id: 5, name: '礼盒套装', icon: '🎁' },
  { id: 6, name: '限定款', icon: '✨' }
]
// ...
return product.category === categories.find(c => c.id === selectedCategory)?.name
```

**问题**：
- 首页传的是 `cat_pear` 这种字符串ID，但category页面用数字ID（1,2,3...）做筛选
- category页面的分类名称是"果酒/果汁/气泡酒"，但产品数据的category字段是 `'pear'/'pomegranate'/'hawthorn'`
- 首页传来的 `?category=cat_pear` 在category页面**完全没有被读取和处理**

### 根因2：产品数据分类体系混乱

存在3套互不兼容的分类体系：
1. **MOCK_CATEGORIES** 的 id：`cat_pear` / `cat_pomegranate` / `cat_hawthorn` / `cat_gift`
2. **MOCK_PRODUCTS** 的 category 字段：`pear` / `pomegranate` / `hawthorn` / `gift`
3. **category/index.tsx** 的 categories：数字ID + 中文名称（果酒/果汁/气泡酒/礼盒套装）

三套ID互不对应，导致首页→分类页→产品筛选全链路断裂。

### 根因3：分类名称与实际产品线不符

用户要求的产品线是：
| 品类 | 品牌 | 款数 | 图标 |
|------|------|------|------|
| 🍷 果酒系列 | 邑夏 | 5款 | 桃你欢心/楂香四溢/大吉大梨/似水榴年/葡写浪漫 |
| 🥃 粮食酒系列 | 兴水河 | 3款 | 待定（白酒品类） |
| 🧃 高端NFC果汁系列 | 果粟盈 | 3款 | 待定 |
| 🎁 礼盒套装 | — | — | 组合装 |

但当前代码中的分类是"果酒/果汁/气泡酒/礼盒套装"，没有"粮食酒系列"，"气泡酒"也不存在。

### 根因4：product/index.tsx 详情页永远显示同一个产品

产品详情页硬编码了 `productDetail`（大吉大梨），虽然也定义了 `PRODUCT_LIUNIAN` 和 `PRODUCT_SHANJIAO`，但完全没有根据URL参数 `?id=xxx` 动态切换产品数据。所有产品点击进去都显示同一个页面。

### 四、修复分类页数据筛选

**修改文件：`src/pages/category/index.tsx`**

整体重写分类页，关键修改点：

1. **读取URL参数**：从 `router.params.category` 获取首页传来的分类ID
2. **使用统一分类**：分类标签改为 UNIFIED_CATEGORIES 的4个分类
3. **产品筛选逻辑**：按 `product.category === selectedCategoryId` 筛选
4. **默认选中**：如果URL带了category参数，默认选中对应分类

```tsx
import { UNIFIED_CATEGORIES, UnifiedCategoryId, MOCK_PRODUCTS } from '@/mock/products'
import Taro from '@tarojs/taro'

export default function Category() {
  const router = useRouter()
  const urlCategory = (router.params as any).category as UnifiedCategoryId | undefined
  
  const [selectedCategory, setSelectedCategory] = useState<UnifiedCategoryId | 'all'>(
    urlCategory || 'all'
  )
  
  const categories = [
    { id: 'all' as const, name: '全部', icon: '🏠' },
    ...UNIFIED_CATEGORIES.map(cat => ({ id: cat.id, name: cat.name, icon: cat.icon }))
  ]
  
  const filteredProducts = MOCK_PRODUCTS.filter(product => {
    if (selectedCategory === 'all') return true
    return product.category === selectedCategory
  })

  // ... 其余UI不变，但用 categories 和 filteredProducts 渲染
}
```

## ⚠️ 关键约束

1. **Product interface 的 category 类型**必须改为 `UnifiedCategoryId`，不能用旧的 `'pear' | 'pomegranate' | 'hawthorn' | 'gift'`
2. **粮食酒没有精灵**：spriteId 和 fragments 设为空/0
3. **NFC果汁没有酒精**：alcohol 为 '0%vol'，ageRequired 为 false，详情页不显示年龄验证提示
4. **精灵关联仅限果酒5款**：桃→脾将军、楂→肝谋士、梨→肺丞相、榴→心君、葡→肾智者
5. **首页4个分类图标区域**的图标和文字必须与 UNIFIED_CATEGORIES 完全一致（🍷果酒系列 / 🥃粮食酒系列 / 🧃高端NFC果汁系列 / 🎁礼盒套装）
